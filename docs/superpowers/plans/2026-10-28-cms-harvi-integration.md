# CMS Harvi Integration — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace all static JSON data files in the Alfaterra/Bernardin Astro site with live CMS Harvi API calls, enabling editorial content management without code deploys.

**Architecture:** Astro SSG + CMS Harvi TypeScript client (copied from kit, not npm package). All CMS fetches happen in `.astro` frontmatter at build time. Vercel deploy hook triggers site rebuild on CMS content changes. Bilingual ES/EN handled via `locale` query param — CMS stores one component per page with multilocale tabs.

**Tech Stack:** Astro 7, pnpm, TypeScript, CMS Harvi API (`https://micms.website/api/public/v1`)

**Spec:** `docs/superpowers/specs/2026-10-28-cms-harvi-integration-design.md`

---

## Global Constraints

- CMS API: `https://micms.website/api/public/v1`
- Client slug: `alfaterra-bernardin`
- Production domain: `bernardin.com.ar`
- `output: 'static'` — no SSR, no client-side CMS fetches for content (only for form submits)
- `site.json` stays — non-editable theme data (brand logos, colors, nav links)
- Brand logos stay as static assets in `public/brands/`
- CMS component `key` field: only `a-z`, `0-9`, `_` — no hyphens
- All CMS admin slugs must match current URL segments exactly (builder responsibility)
- `btn_*` fields in CMS data use `{ txt_label, link_url, link_tipo? }` — NOT `CMSLinkField { label, url }` — define custom `CMSBtnField` interface

## Review Focus

1. **`PUBLIC_SITE_ORIGIN` missing → CMS rejects all build-time requests** (`DOMAIN_NOT_ALLOWED`). Must be set in `.env` before any `pnpm build` attempt after Task 1.
2. **Product `[producto]` URL uses `product.slug` from CMS** — if admin enters a slug that doesn't match `slugify(productName)`, those product detail pages 404. Builder verifies parity after loading products to CMS.
3. **`defaultHeaders` not patched in core.ts** → `Origin` header never sent → all requests fail. Task 1 Step 2 patches this; no other task is skippable before it.
4. **News `publishedAt` is ISO 8601; current template uses `DD.MM.YYYY`** — builder formats date in template: `new Date(article.publishedAt ?? article.createdAt).toLocaleDateString('es-AR')` or equivalent.
5. **Contact form has no submit script in current code** — form silently does nothing until Task 4 Step 8 adds the `<script is:inline>`. No other workaround.

```html
      const res = await fetch(endpoint, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(body),
      });
      const json = await res.json();
      if (json.success) {
        e.currentTarget.innerHTML = `<p style="color:green">${json.data?.message ?? '¡Mensaje enviado!'}</p>`;
      } else {
        btn.disabled = false;
        alert('Error al enviar. Intente nuevamente.');
      }
    } catch {
      btn.disabled = false;
      alert('Error de conexión. Intente nuevamente.');
    }
  });
</script>
```
