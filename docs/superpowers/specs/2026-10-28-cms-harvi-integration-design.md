## Intent & Why

Replace static JSON files (`src/data/*.json`) and hardcoded page content with live data from CMS Harvi. The client (Alfaterra/Bernardin) will be able to edit news, products, and page sections from a CMS admin without touching code or triggering manual deploys. Any content change in the CMS triggers an automatic Vercel rebuild.

---

## Goals

- All editorial content (news, products, page copy, contact info) editable from CMS admin
- Bilingual content (ES/EN) preserved
- Zero SSR — site stays Astro SSG (`output: 'static'`), all CMS fetches at build time
- Contact form submits routed to CMS forms API (client-side)
- Vercel deploy hook wired to CMS `rebuild` mode trigger
- No visible regression in site behavior or URL structure

## Non-Goals

- No CMS-driven routing changes (URL slugs stay as-is)
- No ISR / partial revalidation (full rebuild on content change is acceptable)
- No CMS admin UI changes (out of scope for this repo)
- No new features beyond migration of existing content

## Anti-Goals

- Do not use `any` types where CMS types exist
- Do not fetch CMS data client-side for content (only for form submits)
- Do not store credentials in source code

### Bilingual Strategy

Multilocale habilitado en CMS admin para cliente `alfaterra-bernardin`. Todas las entidades (`news`, `products`, `components`) usan `locale` query param. Sin sufijos `_es`/`_en` en claves — el CMS devuelve el valor del locale solicitado. Paginas ES sin `locale` (default `es`), paginas EN pasan `locale: 'en'`.

Sub-categorias de productos son entidades `Category` en CMS (editables): slug = productType del producto, name/description editables desde admin. No se usa `site.json.brandCategories`.

`btn_*` campos devuelven `{ txt_label, link_url, link_tipo? }` — NO `CMSLinkField { label, url }`. Usar interfaz local `CMSBtnField`.

## Builder-Check Resolutions

**Slug parity (products + news + brand categories):** Builder controls CMS admin data entry. Enter slugs that exactly match current URL segments:
- News: `alfaterra-tecnologia-nueva-generacion`, `bernardin-unia-precision`, etc.
- Brand categories: `bernardin`, `unia`, `antonio-carraro`, `samasz`, `casale`
- Products: slugify from product name matching current segment (e.g. `trx-7800`)
Builder ensures parity; no URL changes required.

**News content template:** CMS `NewsItem.content` is HTML string (not `string[]`). Update news detail template from mapping over `body` array to `<div set:html={article.content} />`. Builder's call.

**`PUBLIC_SITE_ORIGIN` on Vercel:** Not needed. `astro.config.mjs` already has `site: "https://bernardin.com.ar"` → `import.meta.env.SITE` = `https://bernardin.com.ar` on all Vercel builds. The `?? import.meta.env.SITE` fallback in `cms.ts` handles it. No Vercel env var needed.
